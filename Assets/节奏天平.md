# 《引力节拍》3D 第一版开发规划

## 1. 项目定位

《引力节拍》是一款采用 **3D 场景表现 2D 音游逻辑** 的原创音游。

游戏核心是：

> 音符拥有不同重量，击中音符后会影响判定线的位置。玩家不仅要按准节奏，还要维持判定线稳定。

第一版目标不是制作完整商业游戏，而是完成一个可玩的核心 Demo，用来验证以下内容：

1. 3D 音符沿轨道飞向判定线是否清晰。
2. A / S / D / F 四键判定是否顺畅。
3. 普通、重、轻、稳定四种音符是否能形成不同手感。
4. 判定线被压低、抬高、回正的表现是否明显。
5. 稳定度系统是否能带来紧张感。
6. Space 主动校准是否能让玩家主动救场。

---

## 2. 核心设计原则

第一版采用：

> **3D 视觉表现 + 2D 时间判定**

也就是说，游戏画面是 3D 的，但音游判定仍然基于音乐时间，而不是基于物理碰撞。

### 2.1 为什么这样做

音游最重要的是判定精准。
如果使用真实物理碰撞来判断音符是否命中，很容易受到帧率、碰撞体、物理更新频率影响。

所以第一版必须遵守：

> 音符位置只是视觉表现，真正判定只看音乐时间。

核心判定方式：

```csharp
float timeDiff = Mathf.Abs(currentMusicTime - note.hitTime);
```

## 3. 第一版游戏形式

第一版采用 **3D 星轨式 4K 音游**。

### 3.1 画面结构

画面中有四条 3D 发光轨道。

```text
Lane A      Lane S      Lane D      Lane F
  │           │           │           │
  │           │           │           │
  ▼           ▼           ▼           ▼

══════════════════════════════════════
              判定线
```

玩家使用：

```text
A / S / D / F
```

分别对应四条轨道。

---

### 3.2 视觉主题

第一版建议采用 **星轨 / 引力 / 能量装置** 风格。

原因：

1. 和“音符有重量”设定天然契合。
2. 不需要复杂人物、场景、动画。
3. 黑色背景 + 发光轨道 + 粒子就能做出不错的效果。
4. 很适合个人开发。

核心视觉元素：

| 元素     | 表现                     |
| -------- | ------------------------ |
| 轨道     | 发光长条 / 星轨          |
| 普通音符 | 蓝白色能量球             |
| 重音符   | 红橙色陨石感音符         |
| 轻音符   | 青色轻盈光粒             |
| 稳定音符 | 绿色 / 金色校准核心      |
| 判定线   | 发光横梁 / 引力线        |
| 背景     | 星空、深色空间、简单粒子 |

## 4. 第一版核心玩法

### 4.1 基础玩法

音符从远处沿轨道飞向判定线。

玩家在音符接近判定线时按下对应按键。

按键对应关系：

| 轨道   | 按键 |
| ------ | ---- |
| Lane 0 | A    |
| Lane 1 | S    |
| Lane 2 | D    |
| Lane 3 | F    |

---

### 4.2 音符重量机制

第一版包含四种音符。

| 音符类型           | 效果                             |
| ------------------ | -------------------------------- |
| 普通音符 Normal    | 基础音符，不改变判定线           |
| 重音符 Heavy       | 击中后压低判定线                 |
| 轻音符 Light       | 击中后抬高判定线                 |
| 稳定音符 Stabilize | 击中后让判定线回正，并恢复稳定度 |

---

### 4.3 判定线偏移机制

判定线不是固定不动的。

重音符会压低判定线：

```text
正常：
════════════════════

被重音符压低：
        ↓
════════════════════
```

轻音符会抬高判定线：

```text
正常：
════════════════════

被轻音符抬高：
════════════════════
        ↑
```

稳定音符会让判定线快速回到默认位置。

---

### 4.4 判定线自动回正

判定线被压低或抬高后，不会瞬间回正，而是有一个自然回弹过程。

第一版建议使用简单弹簧模型：

```csharp
velocityY += -offsetY * springForce * Time.deltaTime;
velocityY *= damping;
offsetY += velocityY * Time.deltaTime;
```

这样可以做出“被重量影响后逐渐恢复”的手感。

---

### 4.5 稳定度系统

游戏使用“稳定度”作为生命值。

稳定度初始值：

```text
100
```

稳定度归零时游戏失败。

稳定度变化规则：

| 行为             | 稳定度变化   |
| ---------------- | ------------ |
| Perfect          | +1           |
| Good             | 0            |
| Bad              | -3           |
| Miss             | -8           |
| 重音符 Miss      | -15          |
| 稳定音符 Perfect | +8           |
| 稳定音符 Good    | +4           |
| 判定线偏移过大   | 持续扣稳定度 |

---

### 4.6 Space 主动校准

玩家可以按 `Space` 主动校准判定线。

校准效果：

1. 消耗校准能量。
2. 让判定线偏移量减少。
3. 让判定线速度降低。
4. 可用于危险时救场。

第一版简化规则：

| 项目                  | 数值             |
| --------------------- | ---------------- |
| 最大校准能量          | 100              |
| 使用消耗              | 30               |
| Perfect 增加          | +3               |
| Good 增加             | +1               |
| 稳定音符 Perfect 增加 | +8               |
| 校准效果              | offsetY *= 0.5   |
| 速度削弱              | velocityY *= 0.3 |

## 6. 游戏流程

### 6.1 基础流程

```text
进入 RhythmTestScene
↓
显示 ReadyPanel
↓
点击 StartButton
↓
播放音乐
↓
根据谱面生成 3D 音符
↓
音符沿轨道飞向判定线
↓
玩家按 A / S / D / F 击打音符
↓
根据时间差判定 Perfect / Good / Bad / Miss
↓
更新分数、连击、稳定度、校准能量
↓
根据音符重量改变判定线
↓
歌曲结束或稳定度归零
↓
显示 ResultPanel
```

| Playing | 游戏进行中           |
| Result  | 歌曲结束，显示结算   |

## 8. 核心系统拆分

### 8.1 `GameManager`

负责整体流程。

职责：

1. 管理游戏状态。
2. 开始游戏。
3. 结束游戏。
4. 失败处理。
5. 控制 ReadyPanel 和 ResultPanel。
6. 判断音乐是否播放结束。

主要字段：

```csharp
public GameState currentState;
public AudioSource musicSource;
```

主要方法：

```csharp
public void StartGame();
public void EndGame();
public void FailGame();
public float GetMusicTime();
```

---

### 8.2 `Note`

负责单个音符。

职责：

1. 保存音符数据。
2. 根据音乐时间更新 3D 位置。
3. 被击中后销毁。
4. 超过判定时间后 Miss。

主要字段：

```csharp
public float hitTime;
public int lane;
public WeightType weightType;

public Vector3 spawnPosition;
public Transform judgePoint;
public float spawnAheadTime;
```

移动逻辑：

```csharp
float timeToHit = hitTime - currentMusicTime;
float progress = 1f - timeToHit / spawnAheadTime;
progress = Mathf.Clamp01(progress);

transform.position = Vector3.Lerp(spawnPosition, judgePoint.position, progress);
```

---

### 8.3 `NoteSpawner`

负责根据谱面生成音符。

职责：

1. 保存谱面数据。
2. 根据当前音乐时间提前生成音符。
3. 设置音符轨道、时间、重量类型。
4. 管理已经生成到第几个音符。

主要字段：

```csharp
public GameObject notePrefab;
public Transform[] spawnPoints;
public Transform[] judgePoints;
public Transform noteRoot;
public float spawnAheadTime = 2f;
public List<NoteData> chartNotes;
private int nextNoteIndex = 0;
```

---

### 8.4 `ChartData`

负责谱面数据。

第一版可以先在 C# 中写死谱面。

数据结构：

```csharp
[System.Serializable]
public class NoteData
{
    public float time;
    public int lane;
    public WeightType weightType;
}
```

重量类型：

```csharp
public enum WeightType
{
    Normal,
    Heavy,
    Light,
    Stabilize
}
```

示例：

```csharp
new NoteData { time = 1.0f, lane = 0, weightType = WeightType.Normal },
new NoteData { time = 1.5f, lane = 1, weightType = WeightType.Heavy },
new NoteData { time = 2.0f, lane = 2, weightType = WeightType.Light },
new NoteData { time = 2.5f, lane = 3, weightType = WeightType.Stabilize },
```

---

### 8.5 `RhythmInput`

负责玩家输入。

职责：

1. 检测 A / S / D / F。
2. 将按键转换为轨道编号。
3. 在对应轨道寻找最接近判定时间的音符。
4. 将音符交给 `JudgeSystem`。
5. 检测 Space 校准输入。

按键对应：

```csharp
KeyCode.A -> lane 0
KeyCode.S -> lane 1
KeyCode.D -> lane 2
KeyCode.F -> lane 3
KeyCode.Space -> 校准
```

---

### 8.6 `JudgeSystem`

负责判定。

职责：

1. 根据当前音乐时间与音符 hitTime 计算时间差。
2. 判断 Perfect / Good / Bad / Miss。
3. 通知分数系统。
4. 通知稳定度系统。
5. 通知判定线系统应用重量效果。
6. 通知特效系统生成命中特效。

判定结果：

```csharp
public enum JudgeResult
{
    Perfect,
    Good,
    Bad,
    Miss
}
```

判定窗口：

```csharp
public float perfectWindow = 0.05f;
public float goodWindow = 0.10f;
public float badWindow = 0.15f;
```

---

### 8.7 `JudgeLineController`

负责判定线偏移与回正。

这是第一版最核心的系统。

职责：

1. 保存判定线基础位置。
2. 保存当前 offsetY。
3. 保存当前 velocityY。
4. 根据音符重量改变 offsetY。
5. 每帧自动回正。
6. 更新 3D 判定线位置。
7. 更新 JudgePointRoot 的位置。
8. 提供 Space 校准接口。
9. 判断偏移是否过大。

主要字段：

```csharp
public Transform judgeLine;
public Transform judgePointRoot;

public float offsetY;
public float velocityY;

public float springForce = 30f;
public float damping = 0.9f;
public float maxOffset = 1.5f;
```

注意：

3D 世界坐标里不要直接使用 2D 规划中的 `20`、`150` 这种 UI 像素数值。

第一版 3D 建议使用：

| 类型      | 偏移量         |
| --------- | -------------- |
| Normal    | 0              |
| Heavy     | -0.25          |
| Light     | +0.18          |
| Stabilize | offsetY *= 0.4 |

---

### 8.8 `StabilitySystem`

负责稳定度。

职责：

1. 保存稳定度。
2. 根据判定结果更新稳定度。
3. 根据判定线偏移持续扣稳定度。
4. 更新 UI。
5. 稳定度为 0 时通知 `GameManager`。

主要字段：

```csharp
public float stability = 100f;
public float maxStability = 100f;
public Slider stabilitySlider;
```

---

### 8.9 `ScoreManager`

负责分数和连击。

职责：

1. 根据判定结果加分。
2. 维护当前连击。
3. 维护最大连击。
4. Miss 时清空连击。
5. 更新 UI。

基础分数：

| 判定    | 分数 |
| ------- | ---- |
| Perfect | 1000 |
| Good    | 700  |
| Bad     | 300  |
| Miss    | 0    |

---

### 8.10 `CalibrationSystem`

第一版可以不单独创建这个脚本，而是把校准逻辑写在 `JudgeLineController` 或 `GameManager` 中。

如果单独拆分，职责如下：

1. 保存校准能量。
2. 根据判定结果增加能量。
3. 按 Space 时检查能量是否足够。
4. 消耗能量并校准判定线。
5. 更新 CalibrationSlider。

主要字段：

```csharp
public float calibrationEnergy = 0f;
public float maxCalibrationEnergy = 100f;
public float calibrationCost = 30f;
```

| Miss             | -8   |
| 重音符 Miss      | -15  |
| 稳定音符 Perfect | +8   |
| 稳定音符 Good    | +4   |

---

### 11.4 3D 判定线偏移

| 音符类型  | 效果            |
| --------- | --------------- |
| Normal    | offsetY += 0    |
| Heavy     | offsetY -= 0.25 |
| Light     | offsetY += 0.18 |
| Stabilize | offsetY *= 0.4  |

---

### 11.5 判定线自动回正

初始参数：

```text
springForce = 30
damping = 0.90
maxOffset = 1.5
```

---

### 11.6 偏移惩罚

| 偏移范围            | 惩罚            |
| ------------------- | --------------- |
| abs(offsetY) < 0.8  | 不惩罚          |
| abs(offsetY) >= 0.8 | 每秒 -5 稳定度  |
| abs(offsetY) >= 1.2 | 每秒 -12 稳定度 |

---

### 11.7 校准能量

| 行为             | 能量变化 |
| ---------------- | -------- |
| Perfect          | +3       |
| Good             | +1       |
| Bad              | 0        |
| Miss             | 0        |
| 稳定音符 Perfect | +8       |
| 使用 Space       | -30      |

Space 校准效果：

```text
offsetY *= 0.5
velocityY *= 0.3
```

## 12. 谱面设计

### 12.1 第一版谱面格式

第一版先在 C# 中写死谱面，不急着做外部 JSON。

每个音符需要：

| 字段       | 说明                   |
| ---------- | ---------------------- |
| time       | 音符应被击中的音乐时间 |
| lane       | 轨道编号               |
| weightType | 重量类型               |

示例：

```csharp
public List<NoteData> notes = new List<NoteData>()
{
    new NoteData { time = 1.0f, lane = 0, weightType = WeightType.Normal },
    new NoteData { time = 1.5f, lane = 1, weightType = WeightType.Heavy },
    new NoteData { time = 2.0f, lane = 2, weightType = WeightType.Light },
    new NoteData { time = 2.5f, lane = 3, weightType = WeightType.Stabilize },
};
```

---

### 12.2 第一首测试谱面结构

第一首测试谱面建议 30 到 60 秒。

分成 5 个阶段。

---

#### 阶段 1：基础按键

时间：0 秒到 10 秒

目标：

让玩家熟悉 A / S / D / F 四轨输入。

只出现普通音符。

```text
Normal Normal Normal Normal
```

---

#### 阶段 2：引入重音符

时间：10 秒到 20 秒

目标：

让玩家感受到重音符会压低判定线。

```text
Normal Normal Heavy Normal
Normal Heavy Normal Normal
```

---

#### 阶段 3：引入轻音符

时间：20 秒到 30 秒

目标：

让玩家理解轻音符可以抬高判定线。

```text
Heavy Heavy Light Normal
Heavy Light Normal Light
```

---

#### 阶段 4：引入稳定音符

时间：30 秒到 40 秒

目标：

让玩家知道稳定音符可以回正判定线并恢复稳定度。

```text
Heavy Heavy Light Stabilize
Normal Heavy Normal Stabilize
```

---

#### 阶段 5：综合段

时间：40 秒到 60 秒

目标：

混合所有音符，测试核心玩法是否成立。

```text
Normal Heavy Light Normal
Heavy Heavy Stabilize Light
Normal Light Heavy Stabilize
```

### 第 4 步：创建音符数据结构

目标：

完成内容：

### 第 5 步：创建 3D 音符预制体

验收标准：

### 第 9 步：实现判定系统

## 15. 后续版本扩展方向

第一版完成后，再考虑以下内容。

### 15.1 第二版：每轨独立偏移

当前第一版是整条判定线一起上下移动。

第二版可以改成每条轨道有独立判定点偏移。

效果：

```text
正常：
════════════════════

左侧下沉：
╲══════════════════

中间下沉：
═══╲╱════════════
```

这样判定线会真正变形。

---

### 15.2 第三版：长按音符重量

加入长按音符。

| 类型     | 效果                   |
| -------- | ---------------------- |
| 重长按   | 按住期间持续压低判定线 |
| 轻长按   | 按住期间持续抬高判定线 |
| 稳定长按 | 按住期间持续恢复稳定度 |

---

### 15.3 第四版：风险倍率

判定线越偏移，风险越高，但分数倍率也越高。

这样高手可以故意在危险状态下游玩，追求高分。

---

### 15.4 第五版：圆形引力模式

将 4K 轨道改成圆形轨道。

音符从外圈飞向中心或从中心飞向外圈。
不同方向的重音符会让圆环判定线产生偏移。

## 16. 第一版开发原则

为了确保项目能做完，第一版必须遵守以下原则：

1. 只做一个测试场景。
2. 只做四条轨道。
3. 只做 Tap 音符。
4. 只做四种重量类型。
5. 只用固定摄像机。
6. 只用时间判定，不用物理碰撞判定。
7. 先用简单模型，不追求复杂美术。
8. 先写死谱面，不做谱面编辑器。
9. 先跑通完整流程，再做特效。
10. 先验证核心手感，再扩展其他玩法。
